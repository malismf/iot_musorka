# Сборка устройства своими руками

Пошаговая инструкция: от распаковки компонентов до устройства, закреплённого
на контейнере и присылающего данные. Каждый этап заканчивается проверкой, чтобы
ошибку было видно сразу, а не после сборки в корпус.

Плата — ESP8266 NodeMCU v2/v3 или Wemos D1 mini, питание от USB.

Время: примерно 2 часа на первое устройство и около часа на каждое следующее.

---

## Что понадобится

**Компоненты** — `hardware/BOM.csv`, **схема подключения** —
`hardware/WIRING.md`.

**Инструменты:** паяльник 40–60 Вт с тонким жалом, припой, флюс, бокорезы,
пинцет, мультиметр, макетная плата, провода Dupont, термоусадка, кабель USB
с данными (не «только зарядка» — частая ошибка).

**Софт:** VS Code + PlatformIO, Python 3.10+, драйвер USB-UART
(CH340 для большинства NodeMCU v3 и D1 mini, CP2102 для NodeMCU v2).

**Техника безопасности:** паяльник кладите на подставку; при пайке
проветривайте; не подавайте 5 В на выводы платы, кроме VIN: входы ESP8266
рассчитаны на 3.3 В.

---

## Этап 0. Проверка платы

Прежде чем что-то соединять, убедитесь, что жива сама плата.

1. Подключите NodeMCU кабелем к компьютеру. В диспетчере устройств
   (или `ls /dev/ttyUSB*` / `ls /dev/cu.*`) должен появиться порт.
2. Залейте прошивку:

   ```bash
   cd firmware
   pio run -e esp8266 -t upload
   pio device monitor        # 115200
   ```

3. В мониторе сразу после сброса появится приглашение консоли:

   ```
   === BINSENSE CONSOLE ===
   id=bin-a1b2c3 fw=2.0.0 hw=esp8266-a02yyuw provisioned=0 claimed=0
   введите help для списка команд
   ```

   Консоль ждёт команду 3 секунды, дальше команды тоже принимаются.
   Если приглашения нет — нажмите кнопку RST на плате.

> Идентификатор `bin-a1b2c3` формируется из MAC-адреса и не меняется.
> Это имя устройства во всей системе.

---

## Этап 1. Макет: индикация и кнопка

Соберите на макетной плате самое простое — светодиод и кнопку.

1. RGB-светодиод: общий катод на землю (G), аноды через резисторы 220 Ом на
   D1, D2, D7.
2. Кнопка: на NodeMCU ничего делать не нужно — это встроенная кнопка FLASH
   на D3. На D1 mini поставьте кнопку между D3 и G (подтяжка уже на плате).

Проверка через консоль:

```
led 255 0 0      → светодиод горит красным
led 0 255 0      → зелёным
led 0 0 255      → синим
button           → «кнопка отпущена» / при нажатой «нажата»
```

Если один из каналов светодиода не работает — чаще всего перепутаны аноды
или не пропаян резистор.

---

## Этап 2. Датчик расстояния

**A02YYUW (основной вариант).** Красный → 3V3, чёрный → G, белый (TX
датчика) → D5, жёлтый (RX датчика) → D6. Прошивка — окружение `esp8266`.

**HC-SR04.** VCC → VIN (5 В от USB; на NodeMCU v3 вывод называется VU),
GND → G, Trig → D5, Echo → D6 **через делитель** 1 кОм / 2 кОм: Echo — 1 кОм —
D6 — 2 кОм — G (датчик отвечает импульсом 5 В, а вход ESP8266 рассчитан на
3.3 В). Прошивка — окружение `esp8266_hcsr04`:

```bash
pio run -e esp8266_hcsr04 -t upload
```

Проверка:

```
measure 5
  1:   832 мм  fill=-1%
  2:   835 мм  fill=-1%
  ...
```

`fill=-1` означает «не откалиброван» — это нормально до этапа 7.

Что должно получиться: измеряя расстояние до пола или стены, вы видите
правильные значения с точностью примерно ±1 см. Разброс в несколько
сантиметров на мягких и неровных поверхностях — тоже норма, поэтому прошивка
берёт медиану из нескольких замеров.

Если приходят нули или пусто:

| Симптом | Причина |
|---|---|
| `-1` на всех замерах, датчик молчит | перепутаны D5/D6, нет питания, прошито не то окружение |
| значения скачут от 20 до 4000 мм | отражения от близких стенок, датчик направлен под углом |
| всегда одно и то же значение ≈ мёртвая зона | объект ближе минимальной дистанции |

---

## Этап 3. Зуммер (необязательно)

База S8050 через 1 кОм к D8, эмиттер на землю, коллектор — к минусу зуммера,
плюс зуммера — к 3V3. Проверка: `beep 2` — два коротких сигнала.

Зуммер стоит именно на D8: при включении этот вывод должен быть притянут к
земле, и база транзистора этому не мешает.

---

## Этап 4. Пайка на макетной плате

Когда всё работает на макете, обвязка переносится на макетную плату, а
NodeMCU вставляется в гребёнки (так плату можно заменить, не перепаивая всё).

Порядок пайки: сначала гребёнки под NodeMCU (вставьте плату, чтобы не
перекосить), затем резисторы, затем транзистор, в конце — провода к датчику,
светодиоду и зуммеру.

Советы:
- сверяйтесь с `hardware/WIRING.md` после каждого узла;
- прозвоните мультиметром питание и землю на короткое замыкание **до**
  первого включения;
- не подключайте ничего, что при включении тянет D3 или D4 к земле, а D8 —
  к питанию: плата не загрузится;
- провода к выносным элементам (датчик, зуммер) делайте с запасом 10–15 см
  и фиксируйте термоклеем — вибрация контейнера рвёт пайку;
- подпишите провода маркером.

После пайки повторите проверки из этапов 1–3: `led`, `button`, `measure`,
`beep`. Удобно пройти их по чек-листу в конце документа.

---

## Этап 5. Прошивка и регистрация

Устройство готовится один раз, скриптом с ноутбука:

```bash
python tools/provision.py \
    --api https://bins.example.com \
    --email admin@bins.example.com \
    --port /dev/ttyUSB0 --flash --env esp8266
```

Скрипт сам: заливает прошивку → читает `id` устройства → регистрирует его на
сервере → получает пароль MQTT и код привязки → записывает их в память
устройства → выводит код привязки и ссылку для привязки в приложении.

Код показывается один раз — перепишите его или сохраните ссылку. Если код
потерян, `provision.py --reset-code` выдаст новый. Сервер на ноутбуке вместо
домена — в [LOCAL_TEST.md](LOCAL_TEST.md).

## Этап 6. Корпус

Корпус — готовая герметичная коробка (например, распаечная IP65), в которую
помещаются NodeMCU с макетной платой.

1. Сделайте в дне отверстие под головку датчика: датчик должен смотреть
   вниз. Стык промажьте силиконом.
2. Кабель питания заведите через гермоввод.
3. Прикрутите плату винтами М2.
4. Светодиод и кнопку выведите в стенку, до которой можно дотянуться, когда
   устройство стоит под крышкой контейнера.
5. Положите пакетик силикагеля и закройте коробку.

Проверка герметичности: подержите собранный корпус под струёй воды 30 секунд,
откройте и убедитесь, что внутри сухо.

---

## Этап 7. Установка на контейнер и калибровка

1. Подключите питание USB (зарядка 5 В). Светодиод мигает синим — устройство
   ждёт настройки Wi-Fi.
2. С телефона подключитесь к точке доступа `BinSense-a1b2c3`, на открывшейся
   странице выберите сеть 2.4 ГГц и введите пароль. Зелёный — получилось.
3. Светодиод медленно мигает бирюзовым — устройство на связи и ждёт привязки.
   Откройте ссылку для привязки из вывода `provision.py` (или пункт меню
   «Добавить» в веб-приложении и введите идентификатор и код), укажите
   название и адрес, отметьте место на карте. После привязки
   устройство мигнёт зелёным три раза и дважды пискнет.
4. Закрепите устройство на крышке **пустого** контейнера.
5. Удерживайте кнопку 3 секунды (светодиод станет фиолетовым) и закройте
   крышку. Через 5 секунд устройство сделает серию замеров и мигнёт
   зелёным три раза — калибровка сохранена. В карточке появится глубина
   контейнера.
6. Короткое нажатие кнопки в любой момент: зелёный — меньше половины,
   жёлтый — больше половины, красный — контейнер заполнен.

Подробности для монтажника — в `docs/USER_GUIDE.md`.

## Чек-лист приёмки устройства

- [ ] `info` в консоли выводит `id`, `prov=1`, адрес сервера;
- [ ] `led`, `beep`, `button` отрабатывают;
- [ ] `measure 5` даёт стабильные значения (разброс < 2 см на ровной поверхности);
- [ ] устройство подключается к Wi-Fi и телеметрия видна в приложении;
- [ ] калибровка сохранена, заполненность считается;
- [ ] корпус закрыт, стык у датчика промазан силиконом;
- [ ] устройство привязано, идентификатор и код привязки записаны.

## Частые проблемы

| Проблема | Что проверить |
|---|---|
| Плата не определяется компьютером | кабель без данных; не установлен драйвер CH340/CP2102 |
| Прошивка не заливается | попробуйте `upload_speed = 115200`; на старых платах зажмите FLASH при сбросе |
| `This chip is ESP32, not ESP8266` | прошивка для ESP8266, а плата — ESP32; нужна плата NodeMCU или D1 mini |
| Консоль выводит иероглифы | скорость монитора должна быть 115200 |
| Плата не загружается после пайки | D3 или D4 притянуты к земле, либо D8 — к питанию |
| Устройство постоянно перезагружается | слабая зарядка или тонкий кабель: нужно 5 В, 1 А |
| Иногда замер повторяется через минуту | уровень резко изменился или датчик дал сбой — прошивка перемеряет через 60 с, это нормально |
| Данные приходят, но заполненность странная | датчик смотрит не вниз, либо калибровка сделана на непустом контейнере |
| Wi-Fi отваливается на улице | проверьте RSSI в Grafana или в строке `[wifi]` консоли при подключении; ниже −85 dBm связь нестабильна |

## Что записывать по ходу сборки

Для раздела презентации «как мы к этому пришли» полезно фиксировать:

- фотографии макета на каждом этапе;
- сравнение датчиков HC-SR04 и A02YYUW в одинаковых условиях;
- неудачные решения (например, замер при открытой крышке — данные бессмысленны;
  без датчика крышки их отсекает повторный замер через минуту).
