# Локальный стенд: сервер на ноутбуке, плата по Wi-Fi

Как проверить всю цепочку без VPS и домена: сервер в Docker на ноутбуке,
плата ESP8266 подключена к нему по Wi-Fi. Инструкция написана для Windows 10/11;
в Linux и macOS шаги те же, кроме брандмауэра.

```
 плата ──Wi-Fi 2.4 ГГц──► точка доступа ──► ноутбук (docker compose)
                        (роутер, хот-спот      ├─ mqtt  :1883  ◄── устройство
                         ноутбука или телефон) ├─ web   :443   ◄── браузер ноутбука
                                               └─ api, ingestor, db, grafana
```

Порядок: сеть → брандмауэр → сервер → подготовка платы → Wi-Fi платы →
привязка → проверка. Всё вместе занимает около получаса.

---

## 0. Что нужно

- **Docker Desktop** (бэкенд WSL 2) — запущен, `docker compose version`
  отвечает. Без Docker — вариант из раздела 3б.
- **Git for Windows** — из него берётся Git Bash для скриптов `*.sh`.
- **Python 3.10+** и пакеты для подготовки платы:

  ```bash
  pip install pyserial httpx platformio
  ```

- **Драйвер USB-UART**: CH340 для большинства NodeMCU v3 и D1 mini, CP2102
  для NodeMCU v2.
  Кабель USB — с линиями данных, а не «только зарядка».
- **Путь к проекту латиницей**, например `C:\binsense`. Путь с кириллицей
  (`C:\учеба\...`) — частая причина, по которой PlatformIO на Windows не
  может собрать прошивку. Docker такой путь переносит, PlatformIO — не всегда.

> Если проект клонирован из git на Windows и контейнер `mqtt` падает с
> ошибкой вида `/bin/sh^M: not found` — у скриптов окончания строк CRLF.
> В репозитории лежит `.gitattributes`, который это исключает, но только
> для клона, сделанного после его появления. Проще всего клонировать
> репозиторий заново.

## 1. Сеть: плата и ноутбук должны видеть друг друга

ESP8266 работает **только в диапазоне 2.4 ГГц** и только с сетями по паролю
(WPA2-PSK). Университетский Wi-Fi со входом через браузер или по логину
(WPA2-Enterprise) не подойдёт. Годится любой из вариантов:

| Вариант | Адрес ноутбука для устройства | Когда удобен |
|---|---|---|
| **А. Мобильный хот-спот Windows** | всегда `192.168.137.1` | в аудитории: не зависит от чужого Wi-Fi |
| Б. Домашний роутер | IPv4 беспроводного адаптера из `ipconfig`, например `192.168.1.23` | дома; адрес лучше закрепить в DHCP роутера |
| В. Точка доступа на телефоне | IPv4 из `ipconfig`, например `192.168.43.10` | если хот-спот ноутбука не запускается |

**Вариант А.** Параметры → Сеть и Интернет → Мобильный хот-спот. Задайте имя
и пароль сети, в «Диапазон сети» выберите **2,4 ГГц**, включите. Windows
раздаёт через хот-спот другое подключение (Wi-Fi или кабель): без него
хот-спот может не включиться.

**Варианты Б и В.** Узнайте адрес ноутбука:

```powershell
ipconfig
# «Адаптер беспроводной локальной сети Беспроводная сеть» → IPv4-адрес
```

Адаптеры `vEthernet (WSL)`, `VirtualBox`, VPN не подходят — нужен тот, что
смотрит в ту же сеть, что и плата. Гостевые сети роутеров часто изолируют
клиентов друг от друга; в такой сети плата ноутбук не увидит.

Без интернета в этой сети стенд тоже работает: плата не синхронизирует время
по NTP, и время замера ставит сервер. Не будут работать только плитки карты
OpenStreetMap и Telegram.

## 2. Брандмауэр Windows: открыть порт 1883

PowerShell **от имени администратора**:

```powershell
New-NetFirewallRule -DisplayName "BinSense MQTT" -Direction Inbound `
    -Protocol TCP -LocalPort 1883 -Action Allow
```

Если при первом запуске Docker Desktop спросил доступ к сети — разрешите
и для частных, и для общественных сетей: сеть хот-спота Windows часто
считает общественной.

## 3. Сервер

В Git Bash, из корня проекта. Третий аргумент — адрес ноутбука из шага 1:
его сервер выдаст устройству как адрес брокера.

```bash
cd /c/binsense
./infra/scripts/init-env.sh localhost admin@binsense.local 192.168.137.1
docker compose up -d --build        # первая сборка — 3–5 минут
docker compose ps                   # всё running / healthy
curl -k https://localhost/api/health
```

Скрипт напечатает пароль администратора — сохраните его. Если третий
аргумент не указать, скрипт подставит адрес основного сетевого интерфейса;
проверьте его в строке «брокер MQTT» — это может оказаться адрес VPN или
виртуального адаптера.

Проверьте, что брокер виден по этому адресу (PowerShell):

```powershell
Test-NetConnection 192.168.137.1 -Port 1883     # TcpTestSucceeded : True
```

Откройте в браузере ноутбука `https://localhost`. Сертификат у Caddy
самоподписанный: «Дополнительно» → «Перейти на сайт». Войдите под
`admin@binsense.local` и паролем из `init-env.sh`.

**Сменился адрес ноутбука** (другая сеть, роутер выдал новый): поправьте
`MQTT_PUBLIC_HOST` в `.env`, выполните `docker compose up -d` и заново
подготовьте плату (шаг 4) — адрес брокера хранится в памяти устройства.

### 3б. Без Docker (Windows)

Если Docker Desktop не поставить (нет прав администратора или WSL 2), сервер
запускается нативно: PostgreSQL, Mosquitto и Caddy скачиваются в
`%USERPROFILE%\binsense-run`, сервисы Python — в отдельное окружение там же.
Нужны Python 3.12+, Node.js, Git for Windows и 7-Zip; права администратора
не нужны.

```powershell
# один раз: .env, база, брокер, Caddy, зависимости, сборка фронтенда
powershell -ExecutionPolicy Bypass -File infra\windows\setup.ps1 -HostAddress 192.168.137.1
# запуск и остановка
powershell -ExecutionPolicy Bypass -File infra\windows\start.ps1
powershell -ExecutionPolicy Bypass -File infra\windows\stop.ps1
```

Сайт открывается по HTTP на всех интерфейсах (`http://localhost`, с других
устройств — `http://<адрес ноутбука>`), брокер слушает `1883` на всех
интерфейсах, PostgreSQL и API — только на `127.0.0.1`. Grafana в этом
варианте не запускается. Логи — в `%USERPROFILE%\binsense-run\logs`.

Для доступа с других устройств нужно правило брандмауэра и для порта 80
(PowerShell от имени администратора, вместе с правилом из шага 2):

```powershell
New-NetFirewallRule -DisplayName "BinSense web" -Direction Inbound `
    -Protocol TCP -LocalPort 80 -Action Allow
```

Сменился адрес ноутбука — повторите `setup.ps1 -HostAddress <новый адрес>`,
перезапустите сервер и заново подготовьте плату.

## 4. Прошивка и подготовка платы

Подключите плату по USB и найдите порт: Диспетчер устройств → «Порты (COM и
LPT)» → например, `USB-SERIAL CH340 (COM5)`.
Закройте `pio device monitor`, если он открыт: порт может занять только одна
программа.

```bash
python tools/provision.py --api https://localhost \
    --email admin@binsense.local --port COM5 --flash --env esp8266
```

Для датчика HC-SR04 — `--env esp8266_hcsr04`. Скрипт заливает прошивку, читает
идентификатор платы, регистрирует её на сервере, записывает в неё адрес
брокера и пароль MQTT и печатает:

```
== Устройство: bin-a1b2c3 (fw 2.0.0, esp8266-a02yyuw)
== Зарегистрировано на сервере: bin-a1b2c3
   код привязки: 7F3K9Q2M
== Записываю настройки в устройство (брокер 192.168.137.1:1883)…
== Устройство настроено
== Ссылка для привязки: https://localhost/claim?id=bin-a1b2c3&code=7F3K9Q2M
```

Сохраните код или ссылку: второй раз код не показывается (новый выдаёт
`--reset-code`).

- Для `https://localhost` скрипт сам не проверяет сертификат: Python не
  доверяет самоподписанному сертификату Caddy.
- Если сервер выдал устройству `localhost`, скрипт откажется записывать
  такой адрес — плата до него не достучится. Укажите адрес явно:
  `--mqtt-host 192.168.137.1`.

## 5. Wi-Fi платы

После подготовки плата поднимает свою точку доступа — светодиод **мигает
синим**.

1. С **телефона** подключитесь к сети `BinSense-a1b2c3`. Если ноутбук сам
   раздаёт хот-спот, настраивайте именно с телефона: Wi-Fi ноутбука занят.
2. Откроется страница настройки (или зайдите на `http://192.168.4.1`).
   Выберите сеть из шага 1, введите пароль, «Save».
3. Светодиод станет зелёным, затем начнёт медленно **мигать бирюзовым** —
   плата подключилась к брокеру и ждёт привязки.

---

## 6. Привязка

Откройте в браузере ноутбука ссылку из вывода `provision.py` — идентификатор
и код подставятся сами. Без ссылки: пункт меню «Добавить» и ввести их
вручную. Заполните название, при желании адрес и место на карте, нажмите
«Привязать». Плата мигнёт зелёным три раза и дважды пискнет.

Плата всё время на связи, поэтому привязать её можно в любой момент —
подтверждение придёт сразу.

## 7. Проверка

**Консоль платы** (Git Bash или PowerShell):

```bash
pio device monitor -p COM5 -b 115200
```

В логе должно быть:

```
[wifi] MyHotspot, -48 dBm, 1830 мс
[mqtt] подключено к 192.168.137.1:1883 за 95 мс
[net] телеметрия: {"seq":1,"boot":...,"fill":...,"wake":"boot",...}
```

**Сервер:**

```bash
docker compose logs -f ingestor               # приём телеметрии
set -a; . ./.env; set +a                     # логин и пароль брокера из .env
docker compose exec mqtt mosquitto_sub -u "$MQTT_ADMIN_USER" \
    -P "$MQTT_ADMIN_PASSWORD" -t 'bins/#' -v  # живой поток сообщений
```

В приложении карточка устройства обновляется сама, по WebSocket.

**Чтобы не ждать 15 минут:**

- короткое нажатие кнопки — замер и немедленная отправка;
- в карточке устройства поставьте «Интервал, с» — 60 и «Heartbeat, с» — 300:
  плата на связи и применит настройки сразу;
- в консоли платы команда `send`.

**Калибровка без контейнера:** направьте датчик на пол или стол с высоты
около метра, удерживайте кнопку 3 секунды (фиолетовый) и уберите руку —
через 5 секунд плата измерит «пустой контейнер». Затем подносите коробку
ближе — заполненность в карточке будет расти. Скачок на 20 % и больше плата
при замере по таймеру перемеряет через минуту: так она отсекает случайные
значения (например, руку в луче), поэтому резкое изменение появится в
карточке с задержкой. При нажатии кнопки повтора нет.

## 8. Если что-то не работает

| Что видно | Причина | Что делать |
|---|---|---|
| `[net] Wi-Fi не настроен`, мигает синим | Wi-Fi платы не задан | шаг 5 |
| Wi-Fi не подключается, три красные вспышки | сеть 5 ГГц, неверный пароль, WPA2-Enterprise | хот-спот 2.4 ГГц; удержание кнопки 10 с — сброс и портал заново |
| `[mqtt] ошибка подключения`, `rc=4` или `rc=5` | брокер отверг логин и пароль: `provision.py` запускали без `--port` или пересоздавали том брокера | повторить шаг 4 с подключённой платой |
| `[mqtt] ошибка подключения` с другим кодом | брокер недоступен по сети | `info` в консоли платы — какой `host` записан; `Test-NetConnection`; правило брандмауэра; плата и ноутбук в одной сети |
| `provision.py`: «Адрес брокера … недоступен» | в `.env` `MQTT_PUBLIC_HOST=localhost` | `--mqtt-host <IP ноутбука>` или правка `.env` |
| `provision.py`: ошибка SSL | `--api` указывает не на `localhost` | добавить `--insecure` |
| `provision.py`: «Не дождался приглашения консоли» | порт занят монитором или неверный COM | закрыть монитор, проверить порт, нажать RESET на плате |
| `pio run` падает на путях к файлам | кириллица в пути к проекту | перенести проект в `C:\binsense` |
| Контейнер `mqtt` перезапускается, в логе `^M` | CRLF в `infra/mosquitto/entrypoint.sh` | см. примечание в шаге 0 |
| Карта серая | нет интернета — плитки OSM не грузятся | привязка и данные работают и так |
| В телеметрии нет поля `ts` | в сети нет интернета | не мешает: время замера ставит сервер, не работает только ночной режим |

Больше о развёртывании и обслуживании сервера — [DEPLOY.md](DEPLOY.md),
о прошивке и консоли — [FIRMWARE.md](FIRMWARE.md).
