# Прошивка

Каталог `firmware/`, среда — PlatformIO + Arduino framework для ESP8266. Плата —
NodeMCU v2/v3 или Wemos D1 mini (один и тот же чип ESP-12, прошивка общая),
питание от USB.

```
firmware/
├── platformio.ini        окружения сборки (esp8266, esp8266_hcsr04, esp8266_jsn)
├── include/config.h      пины, константы, структуры настроек
├── src/
│   ├── main.cpp          основной цикл: связь, кнопка, замер по расписанию, отправка
│   ├── measure.cpp/.h    чистая логика: медиана, кадр датчика, заполненность, интервалы
│   ├── json_lite.cpp/.h  сборка и разбор JSON без внешних библиотек
│   ├── sensor.cpp/.h     UART-датчик (программный UART) и HC-SR04
│   ├── netlink.cpp/.h    Wi-Fi, MQTT (QoS 1), NTP, публикация
│   ├── storage.cpp/.h    настройки во флеше (эмуляция EEPROM с контрольной суммой)
│   ├── indicator.cpp/.h  светодиод и зуммер
│   ├── board.cpp/.h      кнопка, причина перезагрузки, перезапуск
│   └── console.cpp/.h    последовательная консоль (заводская настройка и тесты)
└── hosttest/             тесты логики и пробная сборка на компьютере
```

## Сборка и заливка

```bash
cd firmware
pio run -e esp8266                     # собрать (датчик A02YYUW)
pio run -e esp8266 -t upload           # залить
pio device monitor                     # консоль, 115200

pio run -e esp8266_hcsr04 -t upload    # вариант с HC-SR04
pio run -e esp8266_jsn -t upload       # JSN-SR04T (другая мёртвая зона)
```

Библиотеки ставятся автоматически: `tzapu/WiFiManager` (портал настройки Wi-Fi)
и `256dpi/MQTT` (клиент MQTT с поддержкой QoS 1). Первая сборка скачивает
инструменты ESP8266 — несколько минут, дальше сборка идёт за секунды.

Готовый образ можно залить и без PlatformIO: `firmware.bin` из
`.pio/build/<окружение>/` пишется с адреса `0x0` —
`python -m esptool --chip esp8266 --port COM3 write_flash 0x0 firmware.bin`.

> ArduinoJson намеренно не используется: сообщения плоские, а свой разбор
> (`json_lite`) занимает меньше памяти и полностью покрыт тестами, которые
> выполняются на обычном компьютере.

## Как работает устройство

Устройство питается от USB и не спит: `setup()` один раз готовит плату, а
`loop()` крутится постоянно.

```
 setup(): настройки из флеша → окно консоли 3 с (provision.py) → событие hello
          → нет Wi-Fi? портал настройки
                           ▼
 loop():  консоль ─ кнопка ─ связь (Wi-Fi и брокер, переподключение по таймеру)
                           ▼
          пришли настройки? применить сразу, сохранить во флеш
                           ▼
          пора мерить? 7 замеров → медиана → заполненность
                           ▼
          скачок ≥ 20 % или сбой? ──да──► повторный замер через 60 с
                           ▼
          нужно отправлять? (изменение ≥ delta, событие, heartbeat, кнопка)
                           ▼
          телеметрия по MQTT → следующий замер через интервал
                               (обычный / заполнен / ночь)
```

Связь держится постоянно: Wi-Fi переподключается раз в 30 секунд, брокер — раз
в 10 секунд, пока не получится. Настройки приходят retained-сообщением сразу
после подписки, а новые — как только их сохранили в приложении. Пока
устройство не привязано к аккаунту, светодиод медленно мигает бирюзовым.

Счётчик сообщений и идентификатор включения живут в памяти до перезагрузки.
Настройки, калибровка, учётка MQTT и данные Wi-Fi хранятся во флеше одной
структурой с контрольной суммой: повреждённые данные или данные старой версии
не читаются, а заменяются значениями по умолчанию.

### Замер без датчика крышки

Датчика крышки (геркона) в устройстве нет: оно не знает, открыта ли крышка.
Если замер попал на момент, когда крышку открыли, датчик видит небо, стену или
руку — получается либо сбой (`SENSOR_TIMEOUT`), либо резкий скачок уровня, и
сервер завёл бы ложное событие «вывезен» или «заполнен». Поэтому скачок на
`RECHECK_DELTA_PCT` (20 %) и больше или сбой датчика сначала перепроверяются:
через `RECHECK_DELAY_S` (60 с) устройство меряет снова. Настоящий вывоз или
сбой подтвердится и уйдёт на сервер, случайное значение — нет. Решение
принимает `needsRecheck()` в `measure.cpp`, оно покрыто хост-тестами. При
нажатии кнопки и первом замере после включения повтора нет: рядом человек, ему
нужен ответ сразу.

### Программный UART

Единственный полноценный UART ESP8266 занят консолью USB, поэтому датчик
A02YYUW читается программным UART на D5/D6 (9600 бод). Датчик питается
постоянно и сам шлёт кадры, поэтому перед замером буфер очищается — иначе
медиана посчиталась бы по старым данным.

## Индикация

| Ситуация | Светодиод | Зуммер |
|---|---|---|
| Режим настройки Wi-Fi (точка доступа) | мигает синим | — |
| Wi-Fi настроен | зелёный на 0.8 с | — |
| Ожидание привязки в приложении | медленно мигает бирюзовым | — |
| Устройство привязано | 3 зелёные вспышки | два сигнала |
| Кнопка нажата (замер по требованию) | цвет по заполненности: зелёный < 50 %, жёлтый 50–80 %, красный ≥ порога, бирюзовый — нет калибровки | один сигнал после отправки |
| Удержание кнопки 3 с | фиолетовый | — |
| Калибровка: 5 с, чтобы закрыть крышку, затем замер | мигает фиолетовым | — |
| Калибровка сохранена | 3 зелёные вспышки | длинный сигнал |
| Удержание кнопки 10 с | красный | — |
| Ошибка (датчик или сеть) | 3 красные вспышки | три сигнала |
| Обычная работа | не горит | — |

Кнопка — на D3 (GPIO0), на NodeMCU это встроенная кнопка FLASH. Её нельзя
держать в момент включения: плата уйдёт в режим прошивки.

## Последовательная консоль

После подачи питания консоль три секунды ждёт команду; первая команда держит
окно открытым две минуты — через это окно работает `tools/provision.py`. После
него консоль по-прежнему принимает команды: они разбираются в `loop()`.

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `info` | JSON: идентификатор, версия, адрес сервера, калибровка |
| `prov {"host":…,"port":…,"user":…,"pass":…}` | записать учётные данные сервера |
| `measure [n]` | n замеров расстояния с расчётом заполненности |
| `button` | состояние кнопки |
| `led r g b` | задать цвет светодиода |
| `beep [n]` | проверить зуммер |
| `cal` | калибровка пустого контейнера |
| `send` | измерить и немедленно отправить данные |
| `wifi portal` / `wifi clear` | настройка или сброс Wi-Fi |
| `factory` | сброс настроек (учётная запись MQTT сохраняется) |
| `reboot` | перезагрузить устройство |
| `exit` | закрыть окно консоли после включения |

## Настройки устройства

Значения по умолчанию заданы в `include/config.h`, но рабочие приходят с
сервера в retained-сообщении и сохраняются во флеш:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `interval_s` | 900 | обычный интервал измерений |
| `full_interval_s` | 300 | когда контейнер заполнен |
| `night_interval_s` | 1800 | ночью |
| `night` | 23–7 | границы ночного режима |
| `heartbeat_s` | 7200 | обязательная отправка, даже если ничего не изменилось |
| `delta_pct` | 3 | порог изменения для отправки |
| `full_pct` | 80 | порог «контейнер заполнен» |
| `samples` | 7 | сколько замеров усредняется медианой |
| `empty_mm` / `full_mm` | из калибровки | 0 % и 100 % |
| `tz` | MSK-3 | часовой пояс для ночного режима |

## Проверка без железа

```bash
cd firmware/hosttest
./run.sh
```

Скрипт прогоняет тесты логики (медиана, разбор кадров датчика, расчёт
заполненности, выбор интервала, правило отправки, повторный замер, свой JSON)
и пробно собирает все файлы прошивки с заглушками Arduino/ESP8266 — оба
варианта, с A02YYUW и с HC-SR04. Нужен `g++`; другой компилятор задаётся
переменной `CXX` (например, `CXX=clang++ ./run.sh`).

## Частые доработки

**Другая раскладка пинов.** Добавьте окружение в `platformio.ini` с нужными
`-DPIN_...`; править код не нужно. Не занимайте D3, D4 и D8 тем, что меняет их
уровень при включении: это выводы загрузчика.

**Другой датчик.** Кадр UART у A02YYUW и JSN-SR04T одинаковый, меняются только
`SENSOR_MIN_MM` и `SENSOR_MAX_MM`. Для датчика, который выдаёт данные только по
запросу, добавьте отправку байта `0x55` перед чтением в `Sensor::readOnce()`.

**Поменяли структуру настроек во флеше** (`Storage::Data`) — увеличьте
`STORAGE_VERSION` в `storage.cpp`, иначе прочитаются старые байты. Учётку MQTT
после этого придётся записать заново через `provision.py`.

**MQTT поверх TLS.** Замените `WiFiClient` на `BearSSL::WiFiClientSecure` в
`netlink.cpp`, задайте сертификат и порт 8883. Учтите, что TLS на ESP8266
заметно нагружает память: проверьте свободную кучу.
